# Token Flow - 产品规格文档

## 1. 产品定位

私有化部署的大模型流量监控与分析系统，帮助用户：
1. 监控各 API Key 的流量使用情况和 Token 消耗
2. 识别上下文管理模式的低效使用
3. 提供可操作的优化建议
4. 量化优化带来的节省效果

## 2. 核心设计原则

- **非侵入性**：对现有业务代码改动最小，通过代理或透明拦截获取流量
- **纯分析建议**：不自动改写用户请求，仅在看板中提供分析和建议
- **可扩展性**：检测算法模块化，支持增量添加新的分析方法
- **私有化优先**：数据本地存储，支持明文分析

| `DET-008` | 自定义规则检测 | 用户自定义的检测逻辑 | P2 |

## 5. 分析维度与指标

### 5.1 基础统计

- **流量指标**: 请求数、token消耗、响应时间
- **成本指标**: 按各厂商定价计算的预估费用
- **质量指标**: 错误率、超时率

### 5.2 上下文模式识别

针对每种模式，定义检测信号：

#### Full Context 模式检测
```python
signals = {
    "message_count": messages > 20,           # 消息轮数过多
    "token_growth_rate": growth > 1.5,        # token快速增长
    "repeated_system_prompts": duplicates > 0, # 重复系统提示
    "user_repetition": repeated_queries > 3,   # 用户重复问相似问题
}
```

#### Sliding Window 检测
```python
signals = {
    "window_size": current_window,            # 当前窗口大小
    "truncation_events": count,               # 截断事件次数
    "truncated_value": estimated_loss,        # 估计截断的信息价值
    "optimal_window_suggestion": suggested,   # 建议的窗口大小
}
```

### 5.3 效率评分体系

每个 API Key / 会话 的评分维度：

| 维度 | 权重 | 说明 |
|-----|-----|------|
| Token 利用率 | 30% | 有效token / 总token |
| 上下文健康度 | 25% | 无重复、无冗余 |
| 成本效率 | 25% | 单位成本产出 |
| 模式合理性 | 20% | 当前模式是否适合场景 |

综合评分: **A(90-100) / B(70-89) / C(50-69) / D(<50)**

### 6.2 场景化最优基准

预设场景-策略映射：

| 场景 | 推荐策略 | 说明 |
|-----|---------|------|
| 客服对话 | RAG + Summary | 需要长期记忆但可压缩 |
| 代码补全 | Sliding Window | 短期上下文足够 |
| 文档生成 | Full Context | 需要完整上下文保持连贯 |
| 数据分析 | Function Caching | 重复查询可缓存 |

用户可自定义场景映射。

## 8. 扩展性设计

### 8.1 检测器接口

```python
class ContextPatternDetector(ABC):
    """上下文模式检测器基类"""
    
    @property
    @abstractmethod
    def detector_id(self) -> str:
        pass
    
    @property
    @abstractmethod
    def detector_name(self) -> str:
        pass
    
    @abstractmethod
    def analyze(self, session: Session, request: Request, response: Response) -> AnalysisResult:
        """
        分析请求，返回检测结果
        """
        pass
    
    @abstractmethod
    def get_suggestions(self, result: AnalysisResult) -> List[Suggestion]:
        """
        基于检测结果生成优化建议
        """
        pass
```

## 11. 风险与考虑

1. **隐私合规**: 虽然私有化部署，但需明确告知用户数据存储范围
2. **性能影响**: 异步分析虽不影响延迟，但需控制资源占用
3. **误报率**: 初期简单规则可能误报，需持续优化
4. **厂商API变动**: 需跟进各厂商API格式变化
