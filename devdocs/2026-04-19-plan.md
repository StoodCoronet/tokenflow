## Phase 7 — CCR 调研与实现

**目标**: 研究 claude-code-router (CCR) 的代理/格式转换方案，提炼可复用的设计模式，实现 Phase 5 所需的格式转换能力。

### 7.1 CCR 源码调研 ✅ 完成

CCR 代码位于 `reference/claude-code-router/`，核心在 `packages/core/src/`。

#### Transformer 接口

CCR 的 Transformer 是一个宽松的对象类型，所有方法可选：

```typescript
type Transformer = {
  // 请求流入：外部格式 → 统一格式
  transformRequestIn?: (request, provider, context) => Promise<Record<string, any>>
  // 请求流出：统一格式 → Provider 格式
  transformRequestOut?: (request, context) => Promise<UnifiedChatRequest>
  // 响应流入：Provider 格式 → 统一格式
  transformResponseIn?: (response, context) => Promise<Response>
  // 响应流出：统一格式 → 外部格式
  transformResponseOut?: (response, context) => Promise<Response>
  // 认证处理
  auth?: (request, provider, context) => Promise<any>
  endPoint?: string
  name?: string
}
```

**关键设计**: 4 个方向的方法（In/Out × Request/Response），全部可选，按需实现。

#### Provider Transformer vs Utility Transformer

CCR 有两类 transformer，用同一接口但职责不同：

| 类别 | 作用 | 示例 |
|------|------|------|
| **Provider** | 格式转换（统一格式 ↔ 平台格式） | anthropic, gemini, deepseek, groq, openrouter, vercel, cerebras, vertex-* |
| **Utility** | 行为修改（添加/删除字段、限制 token） | reasoning, maxtoken, tooluse, customparams, forcereasoning, sampling, streamoptions |

Utility transformer 通过配置组合：
```json5
{ transformer: { use: ["reasoning", "maxtoken"], maxtoken: { max_tokens: 4000 } } }
```

#### 请求流程（End to End）

```
请求到达 → 路由解析(model → provider) → transformRequestIn → transformRequestOut
→ auth → 发送到上游 API → transformResponseIn → transformResponseOut → 返回
```

- Streaming: 用 SSEParser/SSESerializer TransformStream + rewriteStream 工具函数
- 每个 Provider transformer 自己处理 stream 格式转换

#### 已有的 Provider Transformers

| Transformer | 格式方向 | 关键特征 |
|-------------|----------|----------|
| openai | 透传（默认格式） | endPoint=/v1/chat/completions |
| anthropic | OpenAI ↔ Anthropic | system 分离、tool_use、thinking block、stream 转换 |
| deepseek | DeepSeek ↔ Unified | reasoning_content → thinking, max 8192 tokens |
| gemini | Unified ↔ Gemini | contents 数组、function calling、x-goog-api-key |
| groq | Groq ↔ Unified | 去 cache_control、去 $schema、tool call ID |
| openrouter | OpenRouter ↔ Unified | 条件处理（Claude vs 其他）、图片 data URI |
| vercel | Vercel AI SDK ↔ Unified | 图片处理、cache control |
| cerebras | Cerebras ↔ Unified | 去 reasoning 字段 |
| vertex-claude | Vertex AI Claude | Google OAuth、streamRawPredict |
| vertex-gemini | Vertex AI Gemini | Google OAuth、streamGenerateContent |

#### 关键设计模式

1. **Unified Abstraction** — 统一格式作中间层，所有 Provider 围绕它转换
2. **Pipeline** — transformer 按序执行，可组合 Provider + Utility
3. **Strategy** — 根据 provider/model 运行时选择 transformer
4. **Stream Processing** — SSEParser/SSESerializer + rewriteStream 处理流式响应
5. **Config-Driven** — JSON 配置声明 transformer 使用和参数

### 7.2 提炼适配方案 ✅ 完成

#### CCR → Token Flow 适配对比

| 维度 | CCR | Token Flow 现状 | 适配方案 |
|------|-----|-----------------|----------|
| Transformer 方向 | 4 向（In/Out × Req/Res） | 2 向（transformRequest + formatRequest） | 采纳 CCR 的 4 向模型 |
| 统一格式 | UnifiedChatRequest | InternalRequest（≈OpenAI） | 保持 OpenAI 作为统一格式 |
| Utility transformer | 有（maxtoken, reasoning 等） | 无 | 暂不实现，Phase 5 只做 Provider |
| Pipeline 组合 | 配置驱动 `use: [...]` | 单个 transformer | 暂用单 Provider transformer |
| Stream | SSEParser/Serializer + rewriteStream | 手动 reader + decoder | 采纳 CCR 的 stream 方案 |
| 注册机制 | TransformerService + Map | 数组 + find() | 改为 Map 注册表 |
| 插件加载 | config path + dynamic import | 无 | 采纳 CCR 的插件加载机制 |

#### 决策

1. **采用 4 向 Transformer 接口**，简化为 Token Flow 场景所需的子集
2. **保持 OpenAI 为统一格式**（InternalRequest），与 CCR 一致
3. **Phase 5 先做国内平台 Provider transformer**，Utility transformer 后续按需加
4. **Stream 处理参考 CCR 的 SSEParser/Serializer 模式**
5. **注册表改 Map**，支持动态注册和插件加载

### 7.3 实现 ⬜ 待开始

基于调研结论，更新 Phase 5 实施计划：

#### 新 Transformer 接口

```typescript
// 重构 packages/server/src/transformers/base.ts
interface Transformer {
  name: string

  // 请求：外部格式 → 统一格式（OpenAI）
  transformRequestIn?(body: unknown, context: TransformContext): Promise<InternalRequest>

  // 请求：统一格式 → Provider 格式
  transformRequestOut?(request: InternalRequest, context: TransformContext): Promise<ProviderRequest>

  // 响应：Provider 格式 → 统一格式（含 stream）
  transformResponseIn?(response: Response, context: TransformContext): Promise<Response>

  // 响应：统一格式 → 外部格式
  transformResponseOut?(response: Response, context: TransformContext): Promise<Response>

  // 认证
  auth?(request: InternalRequest, provider: ProviderConfig): Promise<Record<string, string>>

  // Provider API endpoint
  endPoint?: string
}

interface TransformContext {
  provider: ProviderConfig
  isStream: boolean
  [key: string]: unknown
}
```

## Phase 8 — TUI 重设计（全屏 + 导航回退）

**目标**: 将 `tflow config` 从简单的 inquirer 提示链改为全屏 TUI，支持面板布局和层级导航。

### 当前问题

- 选择菜单后无法返回上一级（inquirer 的 select 是一次性的）
- 没有全屏布局，只是一系列 prompt
- 无法同时展示多个信息面板

### 设计方向

参考 Claude Code / lazygit 风格：
- 全屏接管终端，用 box 面板组织内容
- 侧边栏/顶部菜单导航，ESC 返回上一级
- 实时渲染配置状态

### 技术选型

| 方案 | 特点 |
|------|------|
| **ink** (React for CLI) | React 组件模型，声明式，熟悉度高 |
| **blessed / neo-blessed** | 成熟的全屏 TUI 框架，box/layout 丰富 |
| **terminal-kit** | 轻量，支持全屏 + 面板 |

推荐 **ink** — 与项目 React 技术栈一致，组件化开发效率高。

### 页面结构

```
┌─ Token Flow Config ──────────────────────────────────────┐
│                                                          │
│  ┌─ Navigation ─┐  ┌─ Content ─────────────────────────┐│
│  │ > Providers   │  │ Provider: openai                  ││
│  │   Ports       │  │ Base URL: https://api.openai.com  ││
│  │   Router      │  │ API Key:  sk-xx***                ││
│  │   Detectors   │  │ Models:   gpt-4o, gpt-4o-mini     ││
│  │   General     │  │                                    ││
│  │               │  │ [Add Provider]  [Edit]  [Delete]   ││
│  │               │  │                                    ││
│  │               │  │ ESC 返回 / Enter 编辑 / q 退出     ││
│  └───────────────┘  └────────────────────────────────────┘│
│                                                          │
│  ↑↓ 导航  Enter 选择  ESC 返回  q 退出                    │
└──────────────────────────────────────────────────────────┘
```

### 导航设计

- **主菜单** → 选择配置分类（Providers / Ports / Router / Detectors / General）
- **子页面** → 编辑具体配置项
- **ESC** → 返回上一级
- **q** → 退出 TUI（仅主菜单层级）
- 编辑完成自动保存，返回上一级并显示成功提示
