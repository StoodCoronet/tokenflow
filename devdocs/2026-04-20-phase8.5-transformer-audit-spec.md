# Phase 8.5 — Transformer 层审计与重构

**日期**: 2026-04-20
**基于**: CCR (claude-code-router) 源码审计 + Phase 7 调研结论 + Phase 9 测试需求

---

## 背景

Phase 7 完成了 CCR 调研，并基于调研实现了 Token Flow 的 transformer 层。但通过 Phase 9 测试计划准备阶段的 review，发现当前实现的转换方向与核心业务需求不一致。

### 核心业务

Token Flow 是一个 LLM 代理中转站。用户在各平台购买 API Key，配置到 Token Flow 中，Token Flow 生成统一的 endpoint + key 供客户端使用。

**主要使用场景**：用户在 Claude Code 中配置 Token Flow 的 endpoint 和 key，通过 Token Flow 访问其他平台的模型。

### 问题发现

对比 CCR 源码审计发现：

| 维度 | CCR | Token Flow 当前 | 差距 |
|------|-----|-----------------|------|
| 客户端接口 | `/v1/messages`（Anthropic）+ `/v1/chat/completions` | 仅 `/v1/chat/completions` | 缺 Anthropic 端点 |
| Transformer 层级 | 两层（主 transformer + provider transformer） | 一层（按 provider 选） | 缺主 transformer 层 |
| Anthropic transformer 方向 | Anthropic ↔ IR（双向） | IR → Anthropic（单向，且是上游方向） | 方向反了 |
| Provider transformer | 各平台独立实现 requestIn + responseOut | 仅 transformRequestOut，基本透传 | 功能不完整 |
| Streaming | OpenAI SSE ↔ Anthropic SSE 完整转换 | Anthropic streaming 标注 passthrough | 未实现 |

> **IR** = Intermediate Representation（中间表示），编译原理术语。这里是客户端格式与平台格式之间的统一中间格式。

### CCR 的架构（参考标准）

CCR 使用两层 transformer + IR 的架构：

```
请求方向：
  客户端格式（Anthropic/OpenAI）
    → 主 transformer.transformRequestOut → IR（UnifiedChatRequest）
    → Provider transformer.transformRequestIn → 平台格式
    → 发送到上游

响应方向：
  上游平台响应
    → Provider transformer.transformResponseOut → IR 响应
    → 主 transformer.transformResponseIn → 客户端格式
    → 返回客户端
```

主 transformer 由端点决定：
- `/v1/messages` → Anthropic transformer（Anthropic ↔ IR）
- `/v1/chat/completions` → OpenAI transformer（透传，IR 就是 OpenAI）

### Step 2：重写类型定义（base.ts）

重写 `packages/server/src/transformers/base.ts`，对齐 CCR 的 `types/llm.ts` + `types/transformer.ts` 命名：

```typescript
/** 统一消息格式（IR 消息单元） */
interface UnifiedMessage {
  role: 'user' | 'assistant' | 'system' | 'tool'
  content: string | null | UnifiedContent[]
  tool_calls?: Array<{
    id: string
    type: 'function'
    function: { name: string; arguments: string }
  }>
  tool_call_id?: string
  thinking?: { content: string; signature?: string }
  cache_control?: { type?: string }
}

/** 统一工具定义 */
interface UnifiedTool {
  type: 'function'
  function: {
    name: string
    description: string
    parameters: { type: 'object'; properties: Record<string, any>; required?: string[] }
  }
}

/** IR 请求格式（对齐 CCR 的 UnifiedChatRequest） */
interface UnifiedChatRequest {
  messages: UnifiedMessage[]
  model: string
  max_tokens?: number
  temperature?: number
  stream?: boolean
  tools?: UnifiedTool[]
  tool_choice?: 'auto' | 'none' | 'required' | string | { type: 'function'; function: { name: string } }
  reasoning?: { effort?: ThinkLevel; max_tokens?: number; enabled?: boolean }
}

/** Provider 连接配置 */
interface ProviderConfig {
  api_base_url: string
  api_key: string
  models: string[]
}

/** 发送给上游的格式化请求 */
interface ProviderRequest {
  url: string
  headers: Record<string, string>
  body: unknown
}

/** Transformer 管道上下文 */
interface TransformContext {
  provider: ProviderConfig
  isStream: boolean
  [key: string]: unknown
}
```

引入两层 transformer 接口：

```typescript
/** 主 Transformer — 由客户端端点决定，负责客户端格式 ↔ IR */
interface MainTransformer {
  name: string
  endPoint: string

  // 客户端格式 → IR
  transformRequestOut(body: unknown, context: TransformContext): Promise<UnifiedChatRequest>

  // IR 响应 → 客户端格式
  transformResponseIn(response: Response, context: TransformContext): Promise<Response>
}

/** Provider Transformer — 由 provider 配置决定，负责 IR ↔ 上游平台格式 */
interface ProviderTransformer {
  name: string

  // IR → 平台格式（构建请求）
  transformRequestIn(request: UnifiedChatRequest, context: TransformContext): Promise<ProviderRequest>

  // 平台响应 → IR（处理响应）
  transformResponseOut(response: Response, context: TransformContext): Promise<Response>

  // 认证
  auth?(request: UnifiedChatRequest, provider: ProviderConfig): Promise<Record<string, string>>
}
```

**方法命名说明**（对齐 CCR）：
- `transformRequestOut`：请求从主 transformer "流出"到 IR（客户端格式 → IR）
- `transformRequestIn`：请求从 IR "流入" provider transformer（IR → 平台格式）
- `transformResponseOut`：响应从 provider transformer "流出"（平台响应 → IR）
- `transformResponseIn`：响应从 IR "流入"主 transformer（IR → 客户端格式）

### Step 3：实现 OpenAI 主 transformer + Provider transformer

OpenAI 是最简单的情况（IR 就是 OpenAI 格式）：

```typescript
// 主 transformer（透传）
class OpenAIMainTransformer implements MainTransformer {
  name = 'openai'
  endPoint = '/v1/chat/completions'

  async transformRequestOut(body: unknown): Promise<UnifiedChatRequest> {
    return body as UnifiedChatRequest
  }

  async transformResponseIn(response: Response): Promise<Response> {
    return response
  }
}

// Provider transformer（透传 + endpoint/headers）
class OpenAIProviderTransformer implements ProviderTransformer {
  name = 'openai'

  async transformRequestIn(request: UnifiedChatRequest, context: TransformContext): Promise<ProviderRequest> {
    return {
      url: `${context.provider.api_base_url}/v1/chat/completions`,
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${context.provider.api_key}`,
      },
      body: request,
    }
  }

  async transformResponseOut(response: Response): Promise<Response> {
    return response
  }
}
```

### Step 4：重写 Anthropic 主 transformer

参考 CCR 的 `anthropic.transformer.ts`，实现 Anthropic ↔ IR 转换：

**transformRequestOut（Anthropic → IR）**：
- Anthropic `system` 字段 → IR `system` message
- Anthropic `tool_result` → IR `tool` message
- Anthropic `tool_use` → IR `tool_calls`
- Anthropic `thinking` → IR `thinking`
- Anthropic tools schema（`input_schema`）→ IR tools schema（`function.parameters`）

**transformResponseIn（IR → Anthropic）**：
- 同步：OpenAI response JSON → Anthropic response JSON
  - `choices[0].message.content` → `content: [{ type: "text", text }]`
  - `tool_calls` → `tool_use` content blocks
  - `finish_reason` 映射（stop→end_turn, length→max_tokens, tool_calls→tool_use）
  - `usage` 字段映射（prompt_tokens→input_tokens, completion_tokens→output_tokens）
- Streaming：OpenAI SSE → Anthropic SSE
  - `message_start` / `content_block_start` / `content_block_delta` / `content_block_stop` / `message_delta` / `message_stop` 事件生成
  - 参考 CCR 的 `convertOpenAIStreamToAnthropic` 实现
  - 支持 text / tool_calls / thinking 内容类型

### Step 6：重构 Proxy Handler

重构 `packages/server/src/proxy/handler.ts`，实现两层 pipeline：

```typescript
async function proxyHandler(request, reply) {
  // 1. 认证（不变）
  const apiKey = authenticate(request)

  // 2. 路由（不变）
  const { providerName, targetModel } = resolveRoute(request, config)
  const provider = getProvider(providerName)

  // 3. 选择主 transformer（按端点）
  const mainTransformer = getMainTransformer(request.url)

  // 4. 选择 provider transformer（按 provider 配置）
  const providerTransformer = getProviderTransformer(providerName) || getProviderTransformer('openai')!

  // 5. 主 transformer：客户端格式 → IR
  const unified = await mainTransformer.transformRequestOut(request.body, ctx)

  // 6. Provider transformer：IR → 平台格式
  const upstream = await providerTransformer.transformRequestIn(unified, ctx)

  // 7. 转发到上游
  const response = await fetch(upstream.url, { ... })

  // 8. Provider transformer：平台响应 → IR
  const irResponse = await providerTransformer.transformResponseOut(response, ctx)

  // 9. 主 transformer：IR → 客户端格式
  const clientResponse = await mainTransformer.transformResponseIn(irResponse, ctx)

  // 10. 记录 + 返回（不变）
  logRequest(...)
  return reply.send(clientResponse)
}
```

### Step 7：注册双端点

在 server 路由注册时，根据主 transformer 的 `endPoint` 注册对应端点：

```typescript
for (const mainTransformer of mainTransformers.values()) {
  fastify.post(mainTransformer.endPoint, proxyHandler)
}
```
